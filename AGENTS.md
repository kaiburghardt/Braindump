# Braindump – agent notes

Personal macOS app (SwiftUI + AppKit NSTextView), Swift Package, no Xcode project. Ad-hoc signed, not notarized; shared only as a zip on GitHub releases (no App Store). Formerly "WriteNotes" (the repo folder still has the old name; `NotesModel.migrateFromWriteNotes()` moves old data/defaults once).

## Language: English everywhere

Everything is English: UI text, code (types, variables, methods), comments, commit messages, README/AGENTS.md, and replies to the user, **even when the user writes or dictates in German**. Only user content stays as written: the notes themselves, and data that has to match it (German keywords in `Heuristic`, German lines in `Resources/TrainingLines.json`, German examples in the Foundation Models prompt).

## Build / run
- `./build.sh` → `build/Braindump.app`; `./build.sh --install` → `~/Applications` + launch (quits the running copy first). `Resources/TrainingLines.json` is copied into the bundle.
- Icon: `Tools/make_icon.sh` (draws `Tools/make_icon.swift`, a kawaii brain with sticky notes → `Resources/AppIcon.icns`).
- Do not run downloaded third-party binaries (e.g. llama.cpp releases); that was blocked by policy. The local model is built from Apple frameworks only.
- `CFBundleDevelopmentRegion` is `en`, so system menus are English.
- `README.md` is the GitHub landing page; its images live in `docs/` (`icon.png` = 512 px from `Resources/AppIcon-1024.png`, `screenshot-dark.png` / `screenshot-light.png` at 1800 px wide, shown via `<picture>` by color scheme). Retake screenshots with a test copy (see below) and English demo notes, opened with `open -g -n` so it stays in the background, then `screencapture -l <windowID> -o`. Force the look with `-wnAppearance dark` or `light` (test mode only), the window stays at its default size (1080 × 720 pt → 2160 px, scaled to 1800 with `sips -Z 1800`). The current screenshots use `-fontFamily "SF Pro" -fontSize 15`, `Tools/ui_test_notes.txt` and a placeholder AI server (`-aiBaseURL https://llm.example.com -aiModel …`) so the AI toolbar buttons show; launch twice (fresh bundle ID each time) so the mini model is trained and makes the suggestion. The download link points to the latest GitHub release; attach `Braindump.zip` (`ditto -c -k --keepParent build/Braindump.app Braindump.zip`) there, don't commit it.

## Data model
- The editor shows plain text without type markers. On disk: `~/Documents/Braindump/Braindump.json` (`NotesFile`: `format` + `notes` → `[StoredNote]`: type, title, details, spaceBefore, created, lastChecked, archived (archive file only), id), written by hand in a fixed key order (`NotesFile.encoded()`). Render/parse round-trips losslessly.
- A **note** = block of consecutive lines (`NoteParser.blocks`); a blank line ends it; a `#` heading starts its own note. Notes are always rendered with ≥1 blank line between them, because nothing else separates them.
- The **type** (`NoteType`: note, todo, done, radar; JSON `watch` = radar) is data in `NotesModel.records[id]`, not text. IDs stay stable while typing via `assignIDs`: exact title key → fuzzy (`TextSimilarity`) → same slot between matched neighbours → new UUID.
- Typed shortcuts (`[ ] `, `[x] `, `🚧 ` at a line start) are converted into the type and removed (`convertTypedMarkers`, async after the edit, skipped during undo/redo). On a detail line they split it into its own note.
- `pendingNewNote`: after ↩ at the end of a one-line to-do, the empty line two below becomes a to-do once typed on (shown as an empty circle).
- First launch without the JSON imports `Notes.txt` (markers → types, old check dates) and moves the old files to `Old text version/`.
- App-internal state (dismissed suggestions, learned labels) lives in `~/Library/Application Support/Braindump/state.json`.

## Architecture (Sources/Braindump)
- `NotesModel` (@MainActor @Observable singleton): editor text → `notes`, `openTodos`, `doneTodos`, `radarItems`, `suggestions`. Autosave 0.5 s after edits + on resign-active/terminate; polls the JSON mtime every 2 s for external edits; never writes if the load failed. Text edits go through `performEdits`, type changes through `applyTypes`; both are undoable and call `breakUndoCoalescing()` first (otherwise one ⌘Z also reverts the typing before).
- Type styling (done = struck through, radar = semibold title) is applied by the model after each recompute (`restyleAfterTyping`, `restyle`, `restyleAll` → `NoteTextView.applyNoteStyles`), because the storage delegate styles before the model knows the new notes.
- `SuggestionEngine`: AI server (if set up, `.server`) → Apple Foundation Models if available → else `LineClassifier` → else `Heuristic`; a model that fails for a batch hands it to the next. Classifies titles of plain notes (the server also sees 2 detail lines and up to 8 of the user's own decisions per label as examples, batches of 30). `Heuristic.rule` (explicit `TODO`, `->`, `Idee:` …) always wins, on every model path. Threshold 0.6.
- `AIService` (`AIService.swift`): any OpenAI-compatible chat server (LiteLLM proxy, OpenAI, local server), set up in Settings → Connections → AI Server. **The repo is public: no server URL, key or model name in code, docs or tests** – defaults are empty and AI stays off until server and model are set; the model comes from the server's `/v1/models` (or is typed in). Key in the Keychain (account `ai`); http only for localhost. `complete(_:task:system:user:schema:)` sends `/v1/chat/completions` with `response_format: json_schema` (strict, built with `Schema`), `reasoning_effort: "low"` and no `temperature`; a 400 naming one of the optional parameters drops it for that model until quit, unreadable JSON gets one retry. Same ephemeral session + `SameHostRedirects` as the link previews.
- AI actions (`AIActions.swift` = prompts/schemas, `NotesModel` "AI actions" = applying): **Tidy Up** (⌃⌘T, note → short title + details, same language, never translate), **Extract To-Dos** (⌃⌘E, selection or note → typed notes inserted below, source stays), **Ask Braindump** (⌘K, `AskView`, whole file as numbered context, answer + note references, nothing stored). Also in the gutter right-click menu and the selection pop-up, only when AI is set up. Rules: every AI edit goes through `performEdits` (one ⌘Z), is only applied if the note's text is still exactly what was sent (else "The note changed …"), Tidy Up is rejected if a link went missing, types come via `pendingTypes`, AI types are not `learn`ed. Model output is cleaned before it goes into the text (`AIActions.cleanTitle/cleanDetails`: no blank lines, typed shortcuts or `#`). While waiting, the note's icon becomes a pulsing purple sparkle (`isAIBusyAt`); results and errors show in a capsule over the editor (`aiNotice`).
- `LineClassifier` (actor): Create ML MaxEnt + BERT-embedding classifiers averaged 50/50, labels todo/radar/note, trained on `TrainingLines.json` + the user's own typed notes/learned labels (×3), cached in Application Support, retrained when ≥3 examples changed. Held-out eval 29/30 with rules.
- `LinkPreviewService`: Jira (REST v3, email + API token) and Notion (API, integration token) previews; tokens in Keychain, cache in Application Support. The Jira token only goes to the site from Settings (links on other hosts get no preview); requests use an ephemeral `URLSession` that refuses cross-host redirects. `NoteParser.urlRanges` only links http(s)/mailto.
- `EditorView` / `NoteTextView`: TextKit 1. Styling in `didProcessEditing` + `fixFontAttribute`; restyles ±1 neighbouring line. Do NOT move styling to `willProcessEditing` (the cursor jumps to the line end on every keystroke). Moving it after the edit (`didChangeText`) doesn't help either.
- Restyling around an edit makes AppKit miss part of the redraw (after deleting a line the text below stayed one line too low, "a line appears twice", until the next edit; the layout itself was right). Hence `redrawVisibleText()` after every change and restyle – keep it, `Tools/ui_test.sh` catches the bug.
- Blank lines stay full height. Half-height blank lines (layout manager delegate, full height only on the cursor's line) were tried and dropped: the notes below jumped whenever the cursor entered or left a blank line.
- `EditorFont`: family from Settings (`fontFamily`, default SF Mono = `monospacedSystemFont`; "SF Pro"/"New York" are the system fonts, everything else by family name) + size; hands out the medium/semibold/bold weights the styling uses, cached. The sidebar sets note text (radar/to-do/suggestion titles 12 pt, to-do details 10 pt) in the same family via `NotesModel.listFont`; labels, headers and buttons stay in the system font. Gutter: pool of `NSImageView` icons (one per visible note) + `NoteBar` lines. Click → `NotesModel.gutterClick`: to-do ⇄ done toggles directly; note and radar icons open a small menu (note: To-Do / Radar; radar: Checked Today / Make It a To-Do / Take Off the Radar). Right-click/ctrl-click → `menu(for:)` with all types. Selection pop-up = `SelectionPopupView`, plain AppKit (no nested `NSHostingView` inside the text view).
- `SidebarView`: Radar section, To-Dos, Suggestions. `ContentView` shows it Xcode-style as a full-height `.inspector` with its own part of the toolbar (only the toggle, at the far right; it stays there while the sidebar is hidden). That split only happens when the editor and its toolbar sit inside a `NavigationStack` and the toggle is declared in the inspector's own `.toolbar` – toolbar items declared on the outside put the inspector under one undivided toolbar. Editor toolbar, left of the sidebar: To-Do and Radar for the note at the cursor (`cursorNoteType`), History. Width persisted in `sidebarWidth`, measured from outside (window − editor width): an `onGeometryChange` on the inspector's content made it ignore `ideal` and always open at its default 270 pt.
- History (`History.swift`, `HistoryView.swift`, ⌘Y): snapshots = plain `NotesFile` JSON per version in `Application Support/Braindump/History/<file>/`, kept for `historyHours` (1/24/168, default 24) and in any case the newest `HistoryStore.minimumEntries` (1000), however old. The model writes one 10 s after the last change (at most 2 min apart while typing) and keeps the state right before text gets deleted (≥8 characters at once, or a run of backspaces reaching 8; typo fixes don't count) – `keepStateBeforeDeletion` must run before `text`/`notes` are updated. `NoteChange.between` diffs two versions by note ID. Restore and Put Back reuse the old IDs (via `matchPool`/`orphans`), so types and dates come back; both are undoable.
- Undo/Redo menu items are replaced by buttons that send `undo:`/`redo:` down the responder chain – SwiftUI's own items stay disabled because it doesn't see the AppKit text view as focused.

## Testing without disturbing the installed app
- Copy `build/Braindump.app`, change `CFBundleIdentifier` (e.g. `local.kai.BraindumpTest`), re-sign ad-hoc, `open -n` it with `--args -notesPath /scratch/Braindump.json`. A same-bundle-id copy shares window restoration with the installed app and may launch windowless.
- `-notesPath` puts the app in test mode: no WriteNotes migration, no backups, separate `Application Support/Braindump-Test` (history included). A `Notes.txt` next to the JSON path is imported on first start.
- `-wnSelfTest /path/out` (`SelfTest.swift`, only together with `-notesPath`): import, typing mid-line, icon menus (items performed via the model – real menus would block), checkbox click, typed `[ ] ` + ↩, radar, pop-up, merge/split, classifier, AI features against `AIStub` (a `URLProtocol` that answers by schema name – no network; checks rule override, Tidy Up keeping type/links, link guard, stale answers, Extract, Ask, and no requests once removed), JSON. Expects notes titled "Max …", "US Priority …" (radar), "Meeting …" and "Design …" in the imported `Notes.txt`; renders the editor to `/path/out.png`, writes `/path/out.partial.txt` after each section and the full log to `/path/out.txt`. Synthetic key/mouse events are dispatched as plain main-queue blocks (`outsideTask`), not from inside the test's Swift task.
- Do NOT call `endUndoGrouping()` by hand or `window.sendEvent` from inside a Swift task in tests: both corrupted the main-executor checks in the test app (crashes in `swift_task_isMainExecutorImpl`, hangs). Undo can't be tested with synthetic events; test it by hand.
- Build scripts: check `./build.sh`'s exit status, not a `grep` of its output (a matching `grep "error"` "succeeds" and runs stale builds).
- `-wnAIProbe /path/out.txt` with `-aiBaseURL … -aiModel … -aiKeyFile /path/key` (test mode): one real request per AI feature against that server, with timings – to check a server/model. Keep the key in a file outside the repo (never on the command line or in the repo) and delete it afterwards. Test copies never read or write the Keychain item.
- `Tools/ui_test.sh` (after `./build.sh`): UI test for drawing glitches. Runs a test copy with `-wnRenderTest` (`RenderTest.swift`, demo notes from `Tools/ui_test_notes.txt`): adds/removes lines (also with key-repeat speed, in a long scrolled document), and after each step the script captures the real window twice – as is and after a forced full redraw – and compares them (`Tools/imgdiff.swift`). The app also compares its layout with a fresh one (`LAYOUT:` lines) and logs copy types, history versions, put-back and restore. Stale pixels only show in real window captures, never in `cacheDisplay`.
- Test copies live in `$TMPDIR`, not in the repo: anything under `~/Documents` makes a new ad-hoc signed copy wait for a Documents permission prompt. A killed test copy may come back windowless next launch (even with `.defaultLaunchBehavior(.presented)`), so the script uses a fresh bundle ID per run.
- **Never activate/bring a test window to the front**: the user's keystrokes then land in it. Read state via files, screenshots (`screencapture -l <windowID>`) and AX queries instead.
- System Events `click at` performs AX actions, not real mouse events. Key codes are layout-dependent (German QWERTZ: ⌘Z is key 16).
